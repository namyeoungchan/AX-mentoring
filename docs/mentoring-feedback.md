# 멘토링 종료 후 기록 수집

- 예약의 `slots.end_time`을 기준으로 확정 또는 완료된 예약의 멘토와 예약한 멘티에게 각각 Discord DM을 보냅니다. 한국시간으로 저장된 기존 슬롯도 그대로 사용합니다.
- 웹에서 새 일정을 등록할 때 종료 시간을 지정합니다. 기존 클라이언트가 종료 시간을 보내지 않는 경우에만 기존 50분 기본값을 유지합니다.
- 웹 스케줄러는 1분마다 요청을 준비하고 봇은 10초마다 발송 큐를 처리합니다. 종료 시각 이후 처리되며 서버 장애·발송 대기량에 따라 지연될 수 있습니다.
- 기능이 처음 적용된 시점 이후 종료되는 예약부터 자동 요청합니다. 재시작 시 적용 시각과 발송 기록을 유지하므로 중단 중 종료된 일정도 복구합니다. 과거 예약 전체에 소급 발송하지 않습니다.

## 응답과 열람

DM의 **멘토링 내용 작성** 버튼 또는 해당 안내 메시지의 **답장**으로 최대 4,000자의 텍스트를 제출합니다. 일반 DM은 수집하지 않습니다. 추가 제출은 기존 내용을 덮어쓰지 않고 별도 응답으로 저장합니다. 버튼은 봇 재시작 후에도 사용할 수 있으며 입력창을 연 상태에서 재시작한 경우 DM의 버튼을 다시 누르면 됩니다.

웹의 **멘토링 일정 → 해당 일정 → 멘토링 기록**에서 멘토·멘티의 답변, 제출 시각, DM 발송 상태를 확인합니다. 기록을 펼치면 30초마다 갱신하며 수동 새로고침도 지원합니다. 관리자와 기존 일정 열람 권한이 있는 담당 멘토만 열람할 수 있습니다. 학생 계정 및 담당 범위 밖 멘토는 API에서도 차단합니다.

수신자가 DM을 차단한 경우 발송 실패가 표시됩니다. 수신 설정을 확인한 후 **DM 발송 재시도**를 누릅니다. 발송 여부가 불확실하면 기존 메시지를 조회하며 무조건 재발송하지 않습니다.

## 저장 및 배포

워크스페이스별 DB의 `lms_mentoring_feedback_requests`에 예약·역할·수신자를, `lms_mentoring_feedback_responses`에 응답 원문·Discord 이벤트 ID·제출 시각을 저장합니다. 발송은 기존 `lms_outbox`를 사용합니다. 예약과 역할에 고유 제약을 두며 Discord 이벤트 ID로 전송 재시도에 따른 중복 저장을 막습니다.

SQLite 및 PostgreSQL(스키마 버전 3) 변경과 백업·복원을 지원합니다. 웹과 봇을 함께 배포해야 하며, 이전 봇은 새 메시지 종류를 가져가지 않습니다. 기존 `LEARNINGOPS_PROVISION_URL`/`LEARNINGOPS_PROVISION_TOKEN`을 사용하므로 새 비밀값은 필요하지 않습니다. DM 실제 발송에는 해당 Discord 서버 참여 및 DM 수신 허용이 필요합니다.
