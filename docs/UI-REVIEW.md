# UI·톤앤매너 검수 — 2026-09-17

관리자 화면 21개를 1440·390·360px에서 확인했습니다. 로그인, 멘토 온보딩, 학생 참여 현황, 첫 로그인 설정과 학생 계정 발급도 역할별 브라우저 흐름으로 확인했습니다. 운영 자료 대신 임시 DB와 테스트 계정을 사용했습니다.

## 반영한 수정

| 확인한 문제 | 수정 |
| --- | --- |
| 워크스페이스 관리자에게 전체 계정 관리 메뉴 노출 | 실제 총관리자에게만 표시, 서버 권한 검사 유지 |
| 신규 계정 발급 화면 아래에 설정 화면 중복 표시 | 페이지 분기 수정, 중복 화면 방지 검증 |
| Discord 자동 발송 미구현이라는 오래된 도움말 | 실제 출결 요약·팀 채팅·개인 DM·공지 발송 동작으로 교체 |
| 설정에 고정된 운영자 이름과 개발·배포 안내 표시 | 데이터 저장 상태와 연결·계정 복구 안내로 변경 |
| 전체 관리자·총괄 관리자 호칭 혼용 | 사용자 화면에서는 총관리자로 통일 |
| 새 학생에게 가입 승인 절차를 안내 | 관리자 계정 발급 → 이름·새 비밀번호 → Discord 참여·인증으로 수정 |
| 멘토의 과제 생성과 알림 배포 구분이 모호 | 팀 과제 생성 및 관리자 배포 요청으로 안내 |
| 작은 보조 글자와 낮은 대비 | 페이지·카드 설명과 설정·프로필 안내의 크기·대비 개선 |
| 모바일 계정 발급 입력란과 버튼이 작음 | 이름·아이디를 세로 배치, 주요 버튼 44px, 폼 입력 16px 적용 |

브랜드의 초록색, 카드 구조, 상태별 색상은 유지했습니다. 안내는 “하세요”, 저장 결과는 “했습니다”, 메뉴는 짧은 명사형을 기준으로 정리했습니다. 기존 가입 신청 화면은 진행 중 신청을 처리할 수 있도록 남기고 새 계정 발급 경로를 안내합니다.

## 검증

- 관리자 화면 21개 × 화면 폭 3개에서 페이지 가로 넘침 없음, 브라우저 실행 오류 없음.
- 로그인·멘토 온보딩·출결 저장/마감/복구·학생 참여·신규 계정 발급을 포함한 관련 브라우저 테스트 9개 통과.
- 관리자·멘토·학생 PDF 각 3쪽: 전체 9쪽 시각 검수, A4·한글 추출·내장 글리프·접속 링크·푸터 여백 검사.
- 표는 모바일에서 표 영역 안의 가로 스크롤로 모든 열을 확인합니다. 360px 미만의 화면이나 모든 보조기술에 대한 접근성 인증을 의미하지 않습니다.
- 실제 운영 Discord 메시지나 학생 계정을 변경하지 않았습니다. 실 Discord 전달 확인은 기존 수업 리허설 항목으로 유지합니다.

자동 화면 검증: lms-web/tests/ui-review.spec.ts. 역할별 가이드: [가이드 다운로드](guides/README.md).

## 과제 관리 (2026-09-19)

- 관리자 과제 목록을 공통 표·상태 탭·필터 디자인으로 통일했습니다. 모바일에서는 카드로 표시하며, 각 과제에서 제출 내역·CSV 다운로드·대상 명단·알림 발송 내역을 확인합니다. 새로고침 후에도 필터와 열린 내역을 유지합니다.
- 웹과 Discord 모두 생성 시 대상 과정에 연결합니다. 과정이 하나면 자동 선택하고, 여러 개면 생성 중 한 번 선택합니다. 과정이 없으면 먼저 등록합니다.
- 과정이 하나인 워크스페이스의 기존 미연결 과제도 자동 연결합니다. 여러 과정이 있는 기존 미연결 과제는 관리자가 대상을 확인해 지정합니다. 이미 지정한 과정은 바꾸지 않습니다.
- 대상 연결과 Discord 알림 발송은 별개입니다. 새 과제 알림은 상세 화면의 ‘과제 배포’로 요청하며, D-1 알림 정책과 중복 발송 방지는 유지합니다.

## 과정 운영·주차별 일정 (2026-09-19)

- 학습 과정 카드의 상세 화면을 ‘개요 / 주차별 일정’ 탭으로 구성했습니다. 공통 모달·탭·버튼·입력 디자인을 재사용합니다.
- 과정 시작·종료 및 일정 수정은 해당 과정의 변경 여부만 검사합니다. 과제 생성, 제출, 봇 활동으로 전체 워크스페이스가 달라져도 저장할 수 있으며, 같은 과정의 동시 편집은 덮어쓰지 않습니다.
- 과정 시작·종료일, 운영 주차(1~52주), 주차별 수업명·날짜·선택 시간·메모를 수정합니다. 같은 주차에 여러 수업을 등록할 수 있습니다. 빈 일정은 시작일부터 7일 간격으로 자동 채울 수 있습니다.
- 수업 일정은 펼치기 목록으로 제공하며 추가·수정·삭제는 ‘일정 저장’으로 함께 반영합니다. 미저장 상태에서 닫으면 변경 취소 여부를 확인합니다. 일정 변경이 기존 출결 원장이나 멘토링 예약을 옮기지는 않습니다.
- 다른 관리자가 같은 과정을 수정하면 입력 내용을 유지하고 충돌을 안내합니다. 최신 과정 불러오기는 사용자가 선택합니다. 운영 기간 밖의 수업 날짜, 주차 범위 초과, 뒤바뀐 수업 시간은 저장하지 않습니다.


## 입퇴실 출석 · 강의 영상 (2026-09-19)

- 수강생의 나의 출결에 오늘 회차별 입실·퇴실 카드와 한국시간 기록을 표시합니다. Discord 시작하기 패널과 같은 기록을 사용하며, 중복 클릭은 최초 시각을 유지합니다. 둘 다 기록하면 자동 출석 처리하고 멘토 정정은 유지합니다.
- 담당 명단과 CSV에 입실·퇴실 시각을 표시합니다. CSV 가져오기는 기존 8열 양식도 지원하며 시각 열은 읽기 전용입니다. 퇴실 누락은 멘토가 확인해 처리합니다.
- 강의 영상 목록·업로드·설정·시청 모달을 공통 초록색 카드·폼·버튼·여백으로 통일했습니다. 목록은 제목·설명 검색, 과정 및 게시 상태 필터를 제공합니다.
- 업로드 준비 중에는 입력과 닫기를 막고 중복 요청을 방지합니다. 전송 진행률·일시 중지·동일 파일 이어 올리기를 유지합니다. 변환 완료 전 게시를 차단하고, 게시 여부와 변환 상태를 구분합니다.
- 시청 모달은 과정명·재생시간·설명과 접을 수 있는 재생 도움말을 제공합니다. 오류는 작업 중인 모달에 한 번만 표시합니다. 모바일 입력 크기와 주요 버튼 44px를 적용했습니다.
- SQLite·PostgreSQL에서 출석의 교차 플랫폼 동시 요청과 권한 경계를 검증합니다. 영상 브라우저 검증은 Vimeo 전송·재생을 모의하며 실제 유료 영상 업로드는 실행하지 않습니다.


## 시작·종료 코드로 강의 출석 정정 (2026-09-19)

- 코드 없는 입퇴실 버튼을 제거했습니다. 시작 코드 생성이 강의 시작, 종료 코드 생성이 강의 종료이며 학생의 두 코드 입력이 입실·퇴실 출석입니다.
- 강의 예정 시간대(한국시간)를 시작 전에 필수 입력하고, 실제 코드 생성 시각과 학생 입퇴실 시각을 구분합니다. 강의 종료와 출결 확정은 각각 표시합니다.
- Discord 패널은 코드 입력 모달을 열고, 웹은 6자리 입력창에서 코드 종류와 회차를 자동 판별합니다. 종료 시 기존 입실 코드를 폐기하며 잘못된 종류·만료 코드·입실 없는 퇴실을 차단합니다.
- 코드 재발급은 최초 강의 시각을 유지하고 학생 재입력은 최초 입퇴실 시각과 멘토 정정을 유지합니다. 기존 자료·확정 출결은 보존합니다.
