# 승인된 멘토링 일정 재조율

승인된 예약의 조 담당 멘토와 수강생이 직접 조율한다. 메인강사와 워크스페이스 관리자는 제안·수락·거절·철회·조율 알림 재발송 권한이 없으며 조율 DM도 받지 않는다.

## 이용 방법

1. 수강생은 LMS **멘토링 일정**, 조 담당 멘토는 **멘토링 관리 → 멘토링 일정 재조율**을 연다. Discord에서는 수강생이 **멘토링 예약 패널 → 내 예약 · 일정 변경**, 조 담당 멘토가 **과제 대시보드 → 승인된 예약 · 일정 조율** 버튼을 누른다. `/reschedule`, `/mybooking`의 **일정 확인 · 재조율**, 승인·조율 DM 버튼도 같은 기능으로 연결된다.
2. **다른 시간 제안**에서 같은 멘토가 등록한 가능 시간을 선택하고 사유와 기존 시간 참석 가능 여부를 입력한다. 시간이 없으면 멘토가 기존 시간 설정 패널에서 가능 시간을 추가한다.
3. 상대방은 **변경 수락**, **제안 거절**, **다른 시간으로 재제안** 중 하나를 선택한다. 제안자는 자신의 제안을 철회하거나 수정할 수 있으며 직접 수락할 수 없다.
4. 상대방이 수락하면 같은 예약의 시간이 바뀐다. 당사자 모두에게 결과 DM을 발송한다.
5. 멘토링 자체를 취소하려면 **예약 취소**에서 사유를 입력한다. **제안 철회**는 예약 취소와 다른 작업이다.

Discord의 사유 입력 창에서는 기존 시간 참석 여부에 `가능` 또는 `불가`를 입력한다. 봇 재시작 뒤에도 DM 버튼으로 최신 상태를 열 수 있다. 이미 열린 응답 화면이 오래되었으면 서버가 처리를 거부하고 최신 상태를 안내한다.

패널 버튼으로 연 예약 목록과 조율 화면은 클릭한 본인에게만 표시된다. 공용 과제 대시보드의 버튼이 보여도 메인강사·관리자의 조율 요청은 서버에서 거부한다. 봇 배포 후 기존 패널의 자동 갱신이 새 버튼을 반영하며, 별도의 패널을 중복 게시하지 않는다.

## 상태와 기한

| 작업 | 결과 |
| --- | --- |
| 변경 제안 / 재제안 | 기존 예약 유지, 제안 시간 임시 확보, 상대방 응답 대기 |
| 상대방 수락 | 새 시간 확정, 이전 시간과 임시 확보 해제, 기존 리마인더 이력 초기화 |
| 거절 / 철회 / 만료, 두 사람 모두 기존 시간 가능 | 기존 확정 예약 유지 |
| 거절 / 철회 / 만료, 한 명이라도 기존 시간 불가 | **재조율 필요** 유지, 제안 시간만 해제 |
| 응답 전에 기존 시작 시간 경과 | **재조율 필요** 유지, 이후의 새 시간을 다시 제안할 수 있음 |
| 사유를 입력하고 예약 취소 | 예약과 임시 확보 해제, 취소 이력·사유 보존, 상대방 DM |

응답 기한은 제안 후 24시간, 아직 지나지 않은 기존 시작 시간, 제안 시작 시간 중 가장 빠른 시점이다. 기한 경과로 자동 승인하거나 멘토링 자체를 취소하지 않는다. 재조율 중에는 기존 시간으로 리마인더나 종료 후 멘토링 기록 요청을 보내지 않는다. 수락 후에는 최종 합의한 시간에 맞춰 처리한다.

변경 제안 시간과 기존 예약은 같은 멘토 또는 수강생의 다른 예약과 겹칠 수 없다. 제안과 수락 양쪽에서 검증하고, Discord의 기존 예약 생성 경로에도 동일한 임시 확보 검사를 적용한다.

## 저장·알림·검증

- 워크스페이스 `lms_records`의 `mentoringCoordination`에 예약별 상태와 버전을 저장한다. `mentoringCoordinationReceipt`는 요청 재전송을 중복 처리하지 않도록 한다. 두 종류 모두 기존 백업·복원 대상이다.
- 예약 변경, 상태, `lms_audit` 이력, `lms_outbox` 알림을 같은 트랜잭션으로 저장한다. SQLite `BEGIN IMMEDIATE`와 기존 PostgreSQL 워크스페이스 쓰기 잠금을 사용한다.
- DM 실패가 예약 변경을 되돌리지는 않는다. 당사자가 LMS에서 실패 상태를 확인하고 재시도한다. 발송 결과가 불확실하면 기존 메시지 확인 절차를 따른다.
- 새 알림 종류 `mentoring_coordination`을 지원하는 봇만 이 알림을 가져간다. 웹과 봇을 함께 배포해야 새 Discord 명령·버튼을 사용할 수 있다.
- 기존 관리자 완료·취소 및 Discord의 이전 취소 버튼으로 진행 중인 조율을 우회할 수 없다.

자동 검증은 `server/mentoring-coordination.test.mjs`, PostgreSQL 공통 시나리오, `tests/test_lms_rescheduling.py`에 있다. 권한·교차 워크스페이스 접근, 중복 요청, 동시 수락/철회, 오래된 버전, 기한 만료, 알림 저장 실패의 롤백, 시간 확보, 취소, 리마인더 및 종료 후 기록 요청을 다룬다.
