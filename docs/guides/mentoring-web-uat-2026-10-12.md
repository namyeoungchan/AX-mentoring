# 멘토링 일정 변경 — 로컬 웹 UAT 결과 (2026-10-12)

## 결론

테스트 학생·조 담당 멘토를 별도 브라우저 세션으로 실제 로그인시켜 로컬 웹 인수 시나리오를 수행했다. 최초 결과는 15/17이었으며, 사용자 요청에 따라 두 결함을 수정한 뒤 **17/17 통과를 두 차례 확인**했다. 최종 실행은 관련 캡처와 PDF 재생성 후에 수행했다. 이 결과를 실제 Discord 검증이나 실사용자의 최종 인수 완료로 표시하지 않는다.

- 대상: `namyeoungchan/AX-mentoring`, `docs/mentoring-rescheduling-guide`. 기준 커밋 `3c53b9effbcdefdb5704e92ba27b74fb4f01183a` 위에 이 보고서와 함께 커밋할 두 결함 수정을 적용했다. 결과 JSON의 `sourceHashes`에 실제 검증한 소스의 SHA-256을 기록했다.
- 구성: 실제 빌드된 React 앱 + 실제 Node HTTP API + 새 임시 SQLite DB + Chrome.
- 주소: `http://127.0.0.1:3047`. 실행 종료 후 서버·브라우저를 정리했다.
- 계정: `webuat.group`, `webuat.student`, 권한 확인용 `webuat.stranger`, `webuat.main`. 일반 비밀번호 검증을 거쳐 로그인했고 세션 쿠키를 미리 주입하지 않았다.
- 테스트 준비만 fixture: 가상 계정·조 배정·Discord 인증 완료 상태·가용 시간·승인 대기 예약. 학생의 최초 신청과 Discord 인증을 실제 수행했다는 의미가 아니다.
- 로컬 API는 가로채거나 가짜 응답으로 대체하지 않았다. 외부 브라우저 요청은 차단했고 실제 Discord 봇은 실행하지 않았다. Google Fonts 등 차단된 외부 리소스로 운영과 글꼴이 다를 수 있다.
- 로컬 검증 과정에서 천안/모코 운영 DB·계정·예약·Render 설정·권한 변경 없음. 사용자는 이번 두 수정·캡처/PDF 반영 및 로컬 UAT와 CI 통과 후 PR 머지·배포를 승인했다. 실제 머지·배포 결과는 PR #107과 해당 커밋의 배포 상태로 별도 확인한다.
- 실사용자 최종 인수: 대기. 이 결과는 에이전트가 대행한 로컬 웹 검증이며 실제 사용자/운영 환경 인수를 대신하지 않는다.

## 수정 완료 1 — 멘토 화면 이동 후 일정 재조율 영역 중복

1. 조 담당 멘토로 로그인해 멘토링 관리에 진입한다.
2. 도움말 → 멘토링 → 승인된 멘토링 일정 변경으로 이동한다.
3. ‘기능 화면 열기’를 누른다.
4. `멘토링 일정 재조율` 영역이 2개 표시된다. 온보딩으로 이동할 때도 이전 재조율 영역이 남는 현상을 관찰했다.

관련 코드: `lms-web/src/InstructorHome.tsx:31-32`. 형제인 `MentoringCoordination`과 `MentoringManagement`/`HelpCenter`가 같은 `key={activeId}`를 사용했다. 재조율 컴포넌트 키를 `coordination:${activeId}`로 분리한 뒤 동일 재현 순서에서 중복·잔류가 사라졌고 개발 모드 중복 키 경고도 발생하지 않았다.

회귀 테스트: 로컬 웹 UAT와 `tests/help-center.spec.ts`에 반복 화면 이동과 영역 개수 검사를 추가했다. 도움말 테스트의 콘솔 오류 검사를 마지막으로 옮겨 후반부 화면 이동의 경고도 놓치지 않게 했다.

## 수정 완료 2 — 멘토 온보딩의 구 안내

수정 전 멘토 온보딩 → 업무 안내 → ‘멘토링 진행’을 펼치면 **‘기존 예약을 취소한 뒤 다시 예약하도록 안내하세요’**가 남아 있었다.

출처: `lms-web/server/staff-flow.mjs:9`의 `mentorGuides` 문구. 새 도움말과 모순되는 내용을 일정 제안·상대방 수락 흐름으로 교체했다.

승인된 예약은 해당 조 담당 멘토/신청 학생이 합의 후 시간을 변경하며, 제안 철회와 예약 취소를 구분한다. 메인 강사는 제안·수락을 대신하지 못함도 명시했다. 서버 문구 테스트를 추가했고 두 멘토 역할의 온보딩 캡처는 해당 항목을 실제 펼친 화면으로 교체했다. 일정 변경 2개·멘토링 2개·온보딩 2개 가이드의 캡처/PDF를 갱신했다.

`lms-web`에서:

```sh
npm run build
DATABASE_URL='' node scripts/run-mentoring-web-uat.mjs
```

Chrome·기존 프로젝트 의존성과 봇 저장소용 Python 의존성이 필요하다. 필요하면 `PYTHON_EXECUTABLE`로 별도의 로컬 테스트 가상환경 Python을 지정한다. 스크립트는 `.env`가 있는 체크아웃과 이미 사용 중인 3047 포트에서 실행을 거부한다. 운영 URL/DB/Discord 토큰을 넣지 않는다. 매 실행마다 새 임시 DB를 만들고 계정의 임시 비밀번호를 로그에 출력하지 않는다. 실패를 숨기지 않고 종료 코드 1과 결과 JSON을 남긴다.

초기 실행의 자동화 로그인 완료 대기 오류는 테스트 도구에서 수정했다. 그 실행은 제품 결함 집계에 사용하지 않았다. 이후 정상 로그인으로 15/17 결과를 두 번 재현했고, 제품 결함 수정 후에는 17/17을 두 번 확인했다.

## 미검증 범위와 다음 단계

- Discord 실제 계정 인증, 최초 예약 신청/시간 등록, 패널 버튼, 실제 DM 수신은 미검증.
- 운영 PostgreSQL·Render에 접속한 UAT는 미실시. CI의 별도 SQLite/PostgreSQL 리허설 결과를 확인하며 운영 데이터는 건드리지 않는다.
- 사용자 승인 범위는 두 결함 수정 → 로컬 UAT·캡처/PDF 검증 → CI 통과 → PR 머지·배포다. 실제 Discord 수신 미검증은 별도로 남기고 완료로 간주하지 않는다.
- 워크스페이스에 관리자가 직접 업로드한 PDF는 기본 파일 배포로 덮어쓰지 않는다. 해당 등록본이 있으면 관리 화면에서 확인 후 별도 교체해야 한다.
