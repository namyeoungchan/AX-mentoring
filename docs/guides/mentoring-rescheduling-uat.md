# 승인된 멘토링 일정 변경 — 캡처와 실환경 UAT

## 검증 구분과 배포 조건

- 로컬 리허설: 임시 SQLite DB, 가상 멘토·학생, 실제 LMS 브라우저 화면. 서버 API를 가로채거나 화면을 재구성하지 않는다. Discord 인증은 로컬 fixture이며 실 인증·DM 발송 성공을 뜻하지 않는다.
- 실환경 UAT: 운영 서비스 내 **테스트-워크스페이스**와 전용 Discord 서버, 실제 테스트 계정 2개로 아래 시나리오를 검증한다. 로컬 결과만으로 실환경 UAT를 통과 처리하지 않는다.
- 현재 실환경 UAT는 테스트 서버·계정 미준비로 **미실시**다. 실 UAT와 운영자의 인수 확인 전에는 PR을 머지하거나 배포하지 않는다.
- 운영의 천안 AX 워크스페이스, 기존 학생 계정, 예약, 출결을 수정·삭제하지 않는다. 요금제·리전·배포 설정·DB 스키마 변경도 이 작업에 포함하지 않는다.

## 준비

1. 관리자 계정으로 **테스트-워크스페이스**를 선택하고 URL의 workspace ID를 기록한다. 이름만 보고 판단하지 않는다.
2. 테스트 전용 Discord 서버를 준비한다. 천안 운영 서버를 옮겨 연결하지 않는다. 한 Discord 서버는 다른 워크스페이스에 중복 연결할 수 없다.
3. 테스트 전용 조와 과정을 만든다. 관리자 권한을 주지 않은 **조 담당 멘토 1명**, **수강생 1명**을 발급하고 동일한 조에 배정한다. 운영 계정의 역할을 바꿔 테스트하지 않는다.
4. 각 LMS 계정에 서로 다른 실제 Discord 계정을 정상 인증한다. 학생 자기소개와 조 배정, 멘토 온보딩·가능 시간 등록을 완료한다. 서로 다른 브라우저 프로필로 로그인한다. 비밀번호·봇 토큰을 PR이나 캡처에 남기지 않는다.
5. 웹·봇에 일정 재조율 기능이 배포돼 있는지 확인한다. 테스트 서버에서 봇 권한·채널 패널·DM 수신을 확인한다. 봇 재배포나 권한 변경이 필요하면 영향 범위를 먼저 검토한다.
6. 충분히 미래인 서로 겹치지 않는 시간 3개를 등록한다. 학생이 실제 신청하고 멘토가 승인한다. 이 예약 ID와 기존 시간을 기록한다.

## 인수 시나리오

각 항목마다 실행자·시각·예약 ID·예상 결과·실제 결과·캡처 경로를 남긴다. 실패하면 원인 확인 후 재시험하고, 미실시를 통과로 표시하지 않는다.

| 항목 | 조작 | 합격 기준 |
| --- | --- | --- |
| 신청·승인 | 학생 신청 → 멘토 승인 | 두 계정에서 같은 승인 예약 확인, 신청·승인 안내 수신 |
| 멘토 제안 | Discord 과제 대시보드 → 승인된 예약 · 일정 조율 → 다른 시간 제안 | 기존 시간 유지, 변경 응답 대기, 학생에게 실제 DM 도착 |
| 학생 수락 | 학생 DM 또는 LMS 멘토링 일정에서 검토·수락 | 동일 예약 ID의 시간이 변경, 양쪽 화면·DM의 시간 일치 |
| 학생 제안 | 내 예약 · 일정 변경에서 다른 시간 제안 | 멘토에게 DM 도착, 본인 제안의 직접 수락 불가 |
| 거절·재제안 | 멘토 거절 또는 다른 시간 제안 | 최신 상태·사유 표시, 재제안에 학생이 응답 가능 |
| 제안 철회 | 제안자가 철회, 기존 시간 참석 가능 선택 | 예약 자체는 유지, 두 사람의 참석 가능 여부에 맞는 상태 |
| 기존 시간 불가 | 기존 참석 불가로 제안한 뒤 거절·철회 | 예약 취소/확정으로 오인하지 않고 재조율 필요 표시 |
| 예약 취소 | 별도 테스트 예약에서 사유를 입력해 취소 | 예약 취소와 제안 철회가 구분되고 상대방에게 사유 전달 |
| 빈 시간 목록 | 가용 슬롯 없는 테스트 예약에서 제안 시도 | 시간 추가 안내, 엉뚱한 멘토/이미 점유된 시간 선택 불가 |
| 권한·낡은 버튼 | 관리자·메인 강사 또는 다른 학생, 과거 DM/열린 화면 | 권한 밖 변경 차단, 최신 상태 확인 안내, 잘못된 시간으로 확정되지 않음 |
| 알림 실패 | 테스트 계정의 DM 수신 설정으로 검증 | 예약 상태 유지, 발송 실패 식별, 수신 설정 복구 후 당사자 재시도 |
| 도움말 | 멘토·학생 각각 새 항목·6단계·PDF 확인 | 역할별 가이드 일치, 오래된 취소·재예약 안내 없음 |

만료·동시 응답·트랜잭션 실패는 자동 시나리오에서 별도 확인한다. 운영 서버의 시각이나 DB를 직접 변경해 재현하지 않는다.

## 캡처 기준

- LMS는 실제 앱 화면을 촬영하고 예시 데이터라는 표기를 유지한다. 번호·테두리는 해당 실제 버튼/입력 영역 위의 오버레이만 사용한다.
- Discord는 실제 클라이언트에서 패널 진입, 시간 선택, 사유 입력, 제안 DM, 수락 결과를 촬영한다. 로컬 LMS 화면을 Discord 화면으로 표기하지 않는다.
- 개인정보·비밀번호·토큰·무관한 서버/대화가 보이지 않게 촬영 영역을 제한한다. 원본을 가공해 성공 상태나 없는 버튼을 만들지 않는다.
- 실제 Discord 캡처는 `help-discord-captures.mjs`에 출처·촬영일·크기·강조 위치를 등록한 뒤 해당 단계와 PDF에 함께 반영한다. 현재 신규 Discord 캡처는 미확보다.
- PDF 업로드로 덮어쓴 워크스페이스 문서는 기본 PDF 배포만으로 교체되지 않는다. 관리자가 대상 역할/기능의 등록본을 확인하고 수정본 교체 또는 기본 PDF 복원을 결정한다.

## 로컬 재현

`lms-web`에서 빌드 후 실행한다. 운영 DB 환경변수나 봇 토큰이 필요하지 않다.

```sh
npm run build
DATABASE_URL='' HELP_GUIDE_IDS=group-rescheduling,student-rescheduling npm run guides:build
DATABASE_URL='' node --test server/help-guides.test.mjs server/mentoring-coordination.test.mjs
PLAYWRIGHT_DATABASE_URL='' npx playwright test tests/help-center.spec.ts
```

캡처 스크립트는 임시 폴더의 위치를 출력한다. 해당 폴더의 `rescheduling-rehearsal.json`은 실제 로컬 브라우저 조작의 검증 결과이며 `discordDelivery: NOT_TESTED`를 유지한다. 임시 DB는 운영 백업이 아니다.

## 2026-10-11 로컬 확인 결과

- 멘토·학생 각 6단계 캡처 성공. 두 역할 모두 제안 시 기존 시간 유지, 본인 제안 직접 수락 불가, 상대방 수락 후 양쪽 시간 일치·예약 ID 유지, 철회 후 예약 유지 확인.
- 서버 회귀 테스트 171개 통과. 도움말 권한/문서 격리 및 일정 재조율 시나리오 포함. 처음에는 Python 저장소 의존성 누락으로 6개가 실패했으나 임시 가상환경에 저장소 요구 버전을 설치한 뒤 171개 모두 재검증했다.
- Python 일정 재조율 테스트 12개 통과. Discord 클라이언트 실 UAT를 대신하지 않는다.
- 도움말 브라우저 테스트 4개 역할 통과. 멘토·학생의 신규 6단계 이미지, PDF 열기, 기능 화면 이동 확인.
- 전체 61개 가이드·224쪽의 한글/글꼴 포함/이미지 강조/페이지 크기 검사 통과. 변경한 PDF 7개의 푸터 겹침 검사 통과.
- `npm run build`, `npm run lint` 통과.
- 발견 사항: 개발 모드에서 멘토링 관리로 이동할 때 기존 `InstructorHome.tsx`의 형제 컴포넌트 2개가 같은 `key={activeId}`를 사용해 React 중복 키 경고가 발생한다. 현재 가이드 PR에서 업무 화면 코드는 변경하지 않았으며 실 UAT 전 별도 확인이 필요하다.
- 미실시: 실제 Discord 계정 인증·패널 조작·DM 수신, 운영 테스트 워크스페이스의 예약 신청/승인, 실사용자 인수 확인, 운영 배포.
