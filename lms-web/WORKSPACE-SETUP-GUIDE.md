# 워크스페이스 관리자 설정 안내

대시보드의 **워크스페이스 시작하기 → 관리자 설정 순서 · 화면과 버튼 안내**를 열면 각 작업 화면으로 바로 이동할 수 있습니다. 아래 표의 이름은 웹에 표시되는 메뉴·버튼 이름입니다.

| 순서 | 담당자 | 화면 → 버튼 | 확인할 결과 |
| --- | --- | --- | --- |
| 1 | 전체 관리자 | 구성원 · 초대 → 참여 권한: 워크스페이스 관리자 → 초대 링크 만들기 | 초대할 아이디·권한·워크스페이스가 맞는지 확인 후 개인 전달 |
| 2 | 초대받은 관리자 | 초대 링크 → 안내된 계정으로 가입 또는 로그인 → 초대 수락 | 선택 메뉴와 대시보드에 해당 워크스페이스 표시 |
| 3 | 워크스페이스 관리자 | Discord 채널 설정 → Discord 빠른 설정 → 운영할 조 수 → 조 구성 저장 | 운영할 조 목록 표시 |
| 4 | Discord 서버 관리자 | Discord에서 서버 생성 → 채널 링크 복사 | 채널의 https://discord.com/channels/… 주소 확보 |
| 5 | 워크스페이스 관리자 | Discord 빠른 설정 → Discord 채널 링크 또는 서버 ID → 서버 연결하고 계속 | 연결된 서버 ID와 구축 작업 표시 |
| 6 | Discord 서버 관리자 | 이 서버에 앱 초대 → Discord 승인 → 내 LMS 인증 | 앱 참여·구축 성공 자동 확인, 코드 복사·Discord 인증 완료 |
| 7 | 워크스페이스 관리자 | 구성원 · 초대 → 참여 권한: 멘토 → 멘토 구분·담당 조 → 초대 링크 만들기 | 초대 내역의 담당 조·권한 확인 |
| 8 | 멘토 | 초대 수락 → 멘토 온보딩 → 기본 정보 저장 → Discord 참여·인증 → 업무 안내 | 해당 워크스페이스의 인증 완료와 안내 3단계 확인 |
| 9 | 관리자 또는 담당 강사 | 가입 승인 → 대상자·팀 확인 → 승인 | 수강생의 Discord 초대·인증 및 팀 반영 |

작업 전 선택된 워크스페이스 이름을 매번 확인하세요. 전체 관리자 권한과 워크스페이스 관리자 권한, Discord의 서버 관리 권한은 각각 다릅니다.

## 진행이 멈췄을 때

| 증상 | 확인과 다음 행동 |
| --- | --- |
| 봇 초대 버튼 없음 | 봇 온라인과 Web heartbeat 연결을 확인합니다. 봇 ID가 확인돼야 초대 버튼이 표시됩니다. |
| 서버 추가 버튼 비활성 | 이미 연결된 서버가 있는지, 상세 설정에서 변경한 기본 채널 구성을 먼저 저장했는지 확인합니다. |
| 구축 작업이 대기 중 | 봇이 대상 서버에 참여했는지와 Web/API 통신 상태를 확인합니다. |
| 채널·역할 구축 실패 | Discord의 채널·역할 관리 권한, 봇 역할의 위치를 확인합니다. 실패 작업의 오류를 확인한 후 재시도합니다. |
| 담당 조를 고를 수 없음 | Discord 채널 설정에서 조 구성을 먼저 저장합니다. |
| 초대가 만료되거나 사용됨 | 구성원 · 초대에서 상태를 확인하고 필요하면 새 초대를 발급합니다. |
| 다른 워크스페이스에서 인증했음 | 각 워크스페이스에서 별도 인증합니다. 해당 워크스페이스의 코드와 Discord 서버를 확인합니다. |
| 저장 충돌·네트워크 오류 | 새로고침 후 저장된 결과를 먼저 확인하고 변경을 다시 적용합니다. |

서버 생성·봇 설치 승인 뒤에도 실제 Discord 채널과 역할이 생성됐는지 확인해야 합니다. 화면의 링크 클릭만으로 구축 완료를 판단하지 않습니다.

빠른 설정은 서버에 저장된 결과를 기준으로 재접속 시 이어집니다. 채널 이름·고정 안내문 편집은 **상세 설정 열기**로 이동하세요. 개인 관리자 인증은 **LMS 인증 시작 → 인증 코드 복사 → Discord에서 인증하기**로 진행하고 완료를 자동 확인합니다. 공용 개발 관리자 계정은 개인 Discord 인증을 하지 않습니다.
