# 워크스페이스 운영

아산 AX는 별도 전역 탭이 아니라 하나의 워크스페이스입니다. 왼쪽 선택기에서 천안 AX·아산 AX·새로 만든 워크스페이스를 전환합니다. 선택한 항목은 URL의 `workspace` 값으로 유지됩니다. 기존 `#asan` 링크도 아산 AX의 봇 연결 화면으로 연결됩니다.

## 생성과 계정 연결

1. 전체 관리자 로그인 → 워크스페이스 선택기 → **새 워크스페이스**.
2. 이름·설명·Discord 서버 ID(선택)를 입력합니다. 새 워크스페이스는 빈 데이터로 시작합니다.
3. **구성원 · 초대**에서 관리자 개인 아이디를 입력하고 **워크스페이스 관리자**로 초대합니다. 해당 계정이 가입·인증·초대 수락을 마치면 관리 권한을 갖습니다.
4. 워크스페이스 관리자가 강사를 같은 방식으로 초대합니다. 강사는 초대 수락 후 수업 관리 화면으로 이동합니다.
5. 수강생은 일반 회원가입에서 워크스페이스를 선택해 신청합니다. 관리자 또는 강사가 승인하면 봇이 Discord 초대 링크를 발급합니다. 서버 참여와 본인 인증 후 학습 화면에 접근합니다.

초대 및 봇 설정의 자세한 절차는 [DISCORD-LMS.md](./DISCORD-LMS.md)를 참고하세요.

| 권한 | 제공 화면과 작업 |
| --- | --- |
| 전체 관리자 | 모든 워크스페이스 조회·생성, 워크스페이스 관리자 지정 |
| 워크스페이스 관리자 | 소속 워크스페이스 운영 데이터·설정, 강사 초대, 수강생 승인 |
| 강사 | 소속 워크스페이스 수업·과제 현황, 출결·성적 입력, 수강생 승인 |
| 수강생 | 본인 가입 신청과 Discord 초대, 참여 완료 후 본인 학습 정보 |

권한은 워크스페이스별로 저장합니다. 한 계정이 A에서는 강사이고 B에서는 수강생일 수 있습니다. API도 매 요청에 소속·권한을 검사합니다. 강사가 전체 운영 설정이나 다른 워크스페이스 데이터를 요청하면 차단합니다. 강사의 현재 운영 범위는 워크스페이스 내 전체 과정이며, 강사별 담당 과정 제한은 별도 기능입니다.

## 저장소와 기존 데이터

- `BOT_DB_PATH` 파일: 기존 기본 워크스페이스(`default`, 초기 이름 천안 AX)의 운영 데이터와 공통 계정·워크스페이스·권한·초대·신청·봇 연동 레지스트리를 저장합니다.
- `<BOT_DB_PATH 파일명>.workspaces/<워크스페이스 ID>.db`: 아산 AX와 추가 워크스페이스의 운영 데이터입니다. 예: `data/mentoring.db.workspaces/asan-ax.db`.
- 기존 데이터는 기본 워크스페이스에 유지합니다. 기존 아산 Render 수신 스냅샷은 아산 AX에 연결하며, 다른 워크스페이스에 복제하지 않습니다.
- 이전에 인증된 계정의 서버/수강생 연결은 권한 테이블 최초 생성 시 수강생 소속으로 이관합니다. 이후 신규 계정은 초대 수락 또는 가입 승인·Discord 인증이 필요합니다.
- 백업·복원 시 기본 DB와 `.workspaces` 디렉토리를 함께 보존하세요. SQLite WAL을 고려해 서비스를 중지한 파일 백업 또는 SQLite 백업 방식을 사용하세요. API의 영속 볼륨에 두 경로가 모두 포함되어야 합니다.

과정·수강생·출결·성적·멘토링·과제·설정·변경 이력은 워크스페이스 저장소별로 분리합니다. 전환 시 작성 중인 폼을 닫고 이전 조회 요청을 취소합니다. 저장 요청에는 워크스페이스 ID와 해당 데이터 버전을 함께 보냅니다.

## Render 봇 하나로 전체 워크스페이스 관리

Discord 봇은 기존 Render Worker 하나를 사용합니다. 모든 워크스페이스에서 같은 봇 계정과 같은 API 연결 설정을 사용합니다. 워크스페이스를 추가할 때 봇 인스턴스나 토큰·환경변수를 추가하지 않습니다. 웹에서 Discord 서버 ID를 연결하고 그 서버에 기존 봇을 초대하면 됩니다.

봇은 참여한 전체 서버를 보고하고 작업의 `guildId`로 대상 서버를 선택합니다. 채널 구성, 승인된 수강생의 Discord 초대, `/lms인증`이 이 방식으로 동작합니다. 공통 봇 상태는 30초마다 별도로 보고하므로 긴 채널 생성 작업 중에도 갱신됩니다. 90초 이상 상태 보고가 없으면 응답 지연으로 표시하며, 보고에서 사라진 서버는 연결 대기로 표시합니다.

Discord 서버 하나는 워크스페이스 하나에만 연결할 수 있습니다. 다른 워크스페이스에서 같은 서버를 사용하려 하면 충돌로 처리합니다. **Discord 채널 설정**을 저장하면 해당 서버가 선택한 워크스페이스에 연결되고 봇의 관측 상태·작업 이력이 그 안에 표시됩니다.

**봇 연결 현황**에는 같은 공통 봇 정보와 선택한 워크스페이스의 Discord 서버만 표시합니다. 기존 운영 DB 스냅샷은 봇의 `GUILD_ID`와 웹의 서버 연결을 기준으로 해당 워크스페이스에 저장합니다. 봇에서 워크스페이스별 `LEARNINGOPS_SOURCE_ID`를 설정할 필요가 없습니다. 기존 봇 DB의 멘토링·과제 데이터는 현재 아산 운영용이며 다른 워크스페이스에 복제하지 않습니다. 추가 워크스페이스의 과정·출결·성적은 각 웹 저장소에서 관리합니다. 기존 예약/과제 패널 기능을 다른 서버의 웹 데이터까지 자동 연결하는 기능은 별도 범위입니다.

수강생 승인 시에는 워크스페이스에 연결된 서버만 선택할 수 있습니다. 봇이 API에 접속하고 초대를 발급해야 실제 링크가 표시됩니다. 프론트엔드만 배포하거나 승인 버튼만 누른 상태를 실제 Discord 연결 완료로 표시하지 않습니다.

## API

`GET/POST /api/workspaces`는 접근 가능한 목록 조회와 전체 관리자 생성을 제공합니다. 운영 요청은 `/api/workspaces/:id/` 아래의 `workspace`, `teaching`, `me/learning`, `members`, `invitations`, `admissions`, `discord/provision`, `integrations/render`로 구분합니다. 기존 `/api/workspace`는 기본 워크스페이스용 전체 관리자 호환 API입니다.

일반 회원가입은 `/api/auth/student/register`, 본인 신청 내역은 `/api/me/admissions`를 사용합니다. 수강생을 구성원 초대로 바로 등록하는 API는 막고 가입 승인 흐름으로 안내합니다. 초대 발급용 봇 통신은 `/api/integrations/discord/admissions/poll` 및 `/complete`를 사용합니다.

데모 모드도 워크스페이스별 데이터를 브라우저에 분리 저장합니다. 기존 데모 데이터는 기본 워크스페이스로 이어받습니다. 실제 계정·초대·봇 동작은 데모에서 실행하지 않습니다.
