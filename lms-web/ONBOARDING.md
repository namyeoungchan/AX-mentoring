# 서버 온보딩과 팀 배정

## 웹 설정

1. 워크스페이스에서 **Discord 채널 설정**으로 서버 ID를 등록하고 공통 봇을 초대합니다.
2. **학습 과정**을 등록하고 **팀 관리**에서 필요한 팀을 만듭니다. 고정된 팀 수는 없으며 서버당 최대 50개 팀을 연결합니다.
3. **수강생 관리**에서 Discord 사용자 ID·과정·팀을 지정합니다. 자동 역할 부여 대상은 `정상` 상태이며, 웹 가입 승인과 Discord 인증도 완료해야 합니다.
4. **온보딩 · 팀 연동**에서 대상 서버와 연결할 과정을 선택하고 **서버 참여 시 자동 온보딩**을 켭니다. 시작 안내문과 채널 이름을 지정한 뒤 **온보딩 저장 및 적용**을 누릅니다.
5. **적용 완료**를 확인합니다. 이후 팀 추가·이름 변경·수강생 팀 변경은 봇이 30초 주기로 확인해 반영합니다. Discord 처리량에 따라 완료까지 더 걸릴 수 있습니다.

설정 권한은 전체 관리자와 해당 워크스페이스 관리자에게 있습니다. 서버마다 연결할 과정을 선택하며, 다른 워크스페이스의 팀과 구성원은 전달하지 않습니다.

## 참여 흐름

- 서버 참여 이벤트에서 바로 안내를 시작합니다. 텍스트 채널을 열어 보는 동작은 Discord 봇 이벤트로 제공되지 않습니다.
- 처음 안내받는 수강생에게 대기 역할과 DM을 제공합니다. DM이 차단되어 있으면 시작 안내 채널에서 본인만 멘션합니다. 기능을 켰을 때 이미 서버에 있는 구성원도 순차 처리합니다.
- 시작 안내 고정글 또는 DM의 **자기소개 작성** 버튼을 누르면 이름과 소개를 입력합니다. 팀을 직접 고르는 항목은 없습니다.
- 웹 승인·Discord 인증·과정 등록과 자기소개가 완료되면 `LMS 수강생`, `LMS 온보딩 완료`, 배정된 팀 역할을 부여합니다. 팀 미배정이면 수강생 역할까지만 부여합니다.
- 인증된 워크스페이스 관리자·강사는 각각 `LMS 운영자`, `LMS 강사` 역할을 받습니다. 이 역할에는 Discord 서버 관리 권한을 부여하지 않습니다.
- 팀별 카테고리·텍스트·음성 채널은 해당 팀원과 워크스페이스 관리자·강사에게 공개합니다. Discord 서버의 관리자 권한 보유자는 Discord 자체 규칙에 따라 접근할 수 있습니다.
- 팀 변경 시 봇이 관리하던 이전 팀 역할을 회수합니다. 웹 소속이나 정상 수강 상태가 해제되면 수강생·팀 역할을 회수하고 대기 역할로 변경합니다. 기존에 수동 부여한 역할은 건드리지 않습니다.

자기소개와 안내 처리 상태는 봇 DB에 저장해 재시작 후 중복 안내를 방지합니다. 이름 변경 권한이 있으면 온보딩 완료자의 서버 닉네임도 웹 이름과 팀명으로 맞춥니다.

## 채널 고정글

시작하기·자기소개·공지·질문·과제·멘토링·팀 대화 안내문이 포함되어 있습니다. 일반 채널 안내문은 **Discord 채널 설정**에서, 시작 안내문은 **온보딩 · 팀 연동**에서 편집합니다. 음성 채널에는 메시지를 게시할 수 없어 함께 생성된 팀 대화 채널에 안내를 고정합니다.

봇이 표시한 자신의 안내글을 재사용하고 내용이 달라지면 갱신합니다. 사람이 작성한 고정글은 수정하거나 해제하지 않습니다. 기존 일반 채널은 삭제하지 않습니다. 연결 과정을 해제해도 팀 채널과 대화 기록은 보존하며, 자동 처리가 켜진 동안 해당 팀 역할을 구성원에게서 회수합니다. 자동 온보딩 자체를 끄면 기존 역할·채널을 유지하고 변경 처리를 멈춥니다.

## Render 봇 설정

기존 채널 구축 연동 키를 공유하므로 새 환경변수는 없습니다. **웹 서비스와 별도로 실행 중인 봇 서비스에도** 다음 설정이 있어야 합니다.

```dotenv
LEARNINGOPS_PROVISION_URL=https://asanax-learningops-web.onrender.com/api/integrations/discord/provision
LEARNINGOPS_PROVISION_TOKEN=<웹 서비스와 같은 32자 이상 키>
```

[웹 데이터 이관](./BOT-DATA.md) 후 관리 역할·채널 ID와 자기소개 기록은 웹 서비스의 영속 DB에 저장합니다. 봇의 기존 `DB_PATH` 파일은 이관 원본 백업으로 유지합니다. 아직 전환하지 않은 설치는 이 파일을 계속 사용하므로 Render 영속 디스크에 두세요.

Discord Developer Portal에서 **Server Members Intent**를 켭니다. 봇에는 **역할 관리·채널 관리·채널 보기·메시지 보내기·기록 보기·링크 삽입·메시지 고정** 권한을 부여하고 봇 역할을 `LMS` 역할들보다 위에 둡니다. 닉네임 동기화에는 **별명 관리** 권한도 필요합니다. 생성된 `LMS` 역할에 서버 관리 권한을 수동 추가하지 마세요.

`적용 대기`가 지속되면 봇 서비스의 URL·키·배포 로그를 확인합니다. `봇 응답 지연`은 마지막 결과 수신 후 90초가 지난 상태입니다. `적용 실패`에는 권한, 역할 순서, 중복 채널, 팀 수 제한 등의 원인을 표시합니다. 오류를 해결하면 다음 확인 주기에 다시 처리합니다.

검증은 임시 DB와 모의 Discord 객체, 브라우저에서 수행합니다. 실제 서버에서의 DM·채널 생성·역할 부여는 배포 후 확인해야 합니다. Discord 메시지 고정 권한은 [공식 메시지 API](https://docs.discord.com/developers/resources/message#pin-message)를 따릅니다.
