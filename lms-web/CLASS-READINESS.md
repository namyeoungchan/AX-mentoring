## 자동 검증 기록

실행일: 2026-09-17 UTC. 환경: Node 24.21.0, Python 3.12, macOS Chrome, 임시 SQLite DB. 실서버 토큰·실제 학생 데이터·Discord 메시지를 사용하지 않았다.

| 확인 | 결과 | 근거 |
| --- | --- | --- |
| 서버 | 102개 통과 | `npm test` |
| Python | 80개 통과 | 저장소 루트 `python -m unittest discover -s tests` |
| 빌드·정적 검사 | 통과 | `npm run build`, `npm run lint` |
| 브라우저 전체 | 36개 통과 (13+11+12) | `npm run test:rehearsal` |
| 교차 기능 장애 시나리오 | 통과, 위 36개에 포함 | `tests/class-readiness.spec.ts` |

첫 브라우저 전체 실행은 35개 중 33개 통과, 2개는 공유 IP의 관리자 로그인 제한(분당 20회)에 걸려 실패했다. `test:rehearsal`은 테스트를 세 묶음으로 나누고 묶음마다 서버와 임시 DB를 새로 시작한다. 재시도나 보안 제한 해제 없이 전체 시나리오를 실행한다. 각 묶음의 결과는 `test-results/shard-*`에 둔다. CI는 Chromium으로 같은 명령을 실행하며 실패 추적 자료를 7일 보관한다.

재현 방법 (`lms-web`에서 실행, Python 의존성은 저장소의 requirements 및 server/requirements-storage.txt 설치):

```sh
npm ci
npx playwright install --with-deps chromium
npm run lint
npm test
npm run test:e2e
```

별도 Python 환경은 `PYTHON_EXECUTABLE`로 지정한다. 설치된 Chrome을 사용하려면 `PLAYWRIGHT_CHANNEL=chrome npm run test:rehearsal`로 실행한다. 묶음별 재현은 `npx playwright test --shard=1/3`처럼 실행하며 이미 실행 중인 서버를 재사용하지 않는다.

### 자동 검증이 확인한 범위

- 120명 출결 저장·중복 재요청·동시 수정 충돌·담당 조 권한·CSV·마감 정정 및 모바일 화면.
- 공지 미리보기·중복 요청 병합·실패 표시·수동 발송 전환과 메시지 링크 기록. worker 단위 테스트의 불확실한 발송 조회, 권한 실패, nonce 재사용.
- 팀 일괄 변경의 원자적 저장·변경 이력·100명 검증·일부 Discord 역할 실패·봇 재시작 복구 모형.
- 제출과 알림의 동일 트랜잭션 저장, 알림 장애 시 제출 보존, 비공개 대상 검증, 팀 집계, D-1 중복 방지·제출 후 취소.
- 통합 시나리오에서 팀 이동 후 오래된 출결 초안 거부 → 새 명단 저장·마감 → 이동한 팀의 제출 집계 → 공지와 과제 알림 권한 실패 → 새로고침 후 네 기능의 원장 보존.
- WAL을 포함한 여러 SQLite DB 백업·복구, 손상/변조 및 경로 탈출 거부, 기존 복구 대상 덮어쓰기 방지.

자동 검증의 Discord worker 응답은 모의 응답이다. 실제 Discord API 제한·채널 접근·권한 우선순위와 현장 작업자의 수행 능력은 다음 리허설에서 확인해야 한다.

## 실제 스테이징 수업 리허설 — 미수행

사전 입력: 스테이징 URL/워크스페이스 ID/Discord 서버 ID, 배포할 Web·Bot 커밋, 현장 진행자·백업 담당자·개발 연락처. 모두 현재 미확정이다. 비밀 토큰이나 학생 개인정보는 이 문서에 넣지 않는다.

| 순서 | 수행 | 통과 증거 | 현재 |
| --- | --- | --- | --- |
| 1 | 테스트 관리자·담당 멘토·다른 조 멘토·수강생으로 가입/승인/Discord 인증 | 각자 권한과 미인증 차단 화면, 타 조 접근 차단 | 미수행 |
| 2 | 테스트 수강생 2개 조 배정 후 일부 이동, 권한 부족 1명 재시도 | 이전 역할 제거·새 역할 반영, 실패자 식별·복구 시간 | 미수행 |
| 3 | 출결 회차 시작, 일괄 출석+예외, CSV 대체 후 복구·마감·사유 정정 | 인원 합계·최종 원장·정정 이력 대조 | 미수행 |
| 4 | 과정 전체 공지 요청, 작업자 응답 전후 Bot 재시작, 결과 조회 | 실제 채널 메시지 ID·링크와 요청 이력, 중복 없음 | 미수행 |
| 5 | 권한 오류로 공지 실패, 자동 발송 중지 후 수동 게시·완료 기록 | 동일 공지 추가 자동 발송 없음 | 미수행 |
| 6 | 개인/팀 과제 제출, 비공개 운영 채널 새 제출 알림, D-1 안내 | 일반 학생이 운영 채널·다른 팀 내역을 못 봄; DM 실패가 공개 전송되지 않음 | 미수행 |
| 7 | 알림 전 Bot 중단, 제출·출결 저장, Bot 복구 후 대기 알림 처리 | 장애 전후 원장 일치, 중복/누락 대조 | 미수행 |
| 8 | 유지보수 창에서 전체 DB 백업, 별도 위치로 복구하여 확인 | manifest 검증, 학생·제출·출결·outbox 대조, 복구 소요 시간 | 미수행 |
| 9 | 비개발자가 안내서만 읽고 장애 1건의 수동 대체·복구 수행 | 막힌 문장 수정, 수행자/검토자 인수 확인 | 미수행 |

D-1 검증은 KST 기준 다음 날 마감의 테스트 과제로 오전 9시 이후 수행한다. 실서비스 시계를 바꾸지 않는다. 봇 응답 유실 후 발송 결과가 불확실하면 메시지 조회를 먼저 하고, 자동 재발송하지 않는다. 수동 대체는 [CLASS-RUNBOOK.md](./CLASS-RUNBOOK.md)의 기능별 절차를 따른다.
