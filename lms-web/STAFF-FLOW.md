# 워크스페이스 운영 시작 프로세스

## 1. 총괄 관리자: 워크스페이스와 관리자 지정

워크스페이스를 만든 뒤 **구성원 · 초대**에서 참여 권한을 **워크스페이스 관리자**로 선택합니다. 초대받을 사람의 로그인 아이디를 지정하고 발급된 링크를 전달합니다. 초대 대상자는 해당 아이디로 가입하거나 로그인하고 **초대 수락**을 누릅니다. 이 단계에는 Discord 서버와 인증이 필요하지 않습니다. 워크스페이스 관리자는 소속 워크스페이스만 운영하며 총괄 관리자 권한을 받지 않습니다.

## 2. 워크스페이스 관리자: 조 수와 Discord 환경 구축

**Discord 채널 설정 → 운영할 조 설정**에서 과정과 조 수(1~50)를 저장합니다. 과정이 없으면 기본 운영 과정을 만듭니다. 새 과정의 시작·종료일은 생성일이므로 실제 운영 기간은 과정 관리에서 수정합니다. 조 수를 늘려도 기존 조의 ID와 배정은 유지되며, 줄이는 요청은 기존 데이터 보존을 위해 거절합니다.

관리자가 Discord에서 서버를 만들고 개발자 모드로 서버 ID를 복사합니다. 웹의 **서버 추가 및 구축**으로 1:1 연결한 후 **이 서버에 봇 초대**를 누릅니다. 초대 링크는 공통 봇의 연결 정보가 수신되면 표시됩니다. [Discord 공식 OAuth2 방식](https://docs.discord.com/developers/topics/oauth2#bot-authorization-flow)을 사용하며 서버 관리자가 Discord에서 초대를 승인합니다.

기본 역할과 공통 채널은 구축 작업으로 생성됩니다. 조별 역할·비공개 대화·음성 채널은 자동으로 켜진 온보딩 작업이 생성합니다. 기본 구축 상태는 **적용 이력**, 조별 구성과 권한 오류는 **온보딩 · 팀 연동**에서 확인합니다. 봇은 30초 주기로 확인하며 Discord 처리 제한에 따라 더 걸릴 수 있습니다. 역할 순서는 봇 역할이 관리 대상 LMS 역할보다 위여야 합니다.

## 3. 멘토 초대와 담당 조 변경

**구성원 · 초대**에서 멘토를 초대합니다.

- **메인 강사:** 전체 조를 담당합니다. 새 조가 생기면 자동으로 포함합니다.
- **조 담당 멘토:** 담당 조를 하나 이상 선택합니다. 복수 조와 조별 복수 멘토를 지원합니다.

워크스페이스 관리자는 구성원 목록의 **담당 조 변경**으로 언제든 수정할 수 있습니다. LMS 조회·출결·성적 수정 범위는 즉시 바뀌고, 봇은 다음 동기화에서 기존 조 역할을 회수하고 새 조 역할을 부여합니다. 타 워크스페이스 조 배정과 멘토 본인의 담당 범위 변경은 거절합니다. 기존 강사 계정은 호환성을 위해 메인 강사로 유지합니다. Discord 자체 관리자 권한을 가진 사용자는 Discord 규칙에 따라 모든 채널을 볼 수 있습니다.

## 4. 멘토 기본 정보와 Discord 참여

멘토가 초대를 수락하면 **멘토 온보딩** 화면이 열립니다. 활동 이름·전문 분야를 저장하면 봇이 본인에게 표시할 Discord 초대 링크를 발급합니다. 링크는 1회 사용, 최대 24시간 유효하며 웹에서는 23시간까지만 제공합니다. 실패하거나 만료되면 재발급할 수 있습니다.

멘토는 LMS와 Discord에서 자기소개를 작성하지 않습니다. 서버에 참여한 뒤 웹에서 인증 코드를 받고 `/lms인증 코드:...`를 실행합니다. 코드는 해당 워크스페이스 서버에 묶이며, 브라우저가 Discord 사용자 ID를 지정할 수 없습니다. 인증 후 웹의 멘토 기본 정보를 해당 워크스페이스의 멘토링 DB에도 등록하여 `/멘토 설정`에서 슬롯을 만들 수 있습니다. Discord 별명은 활동 이름을 기준으로 `멘토_이름`으로 자동 갱신합니다. 별명 관리 권한과 봇 역할 순서가 필요하며, 서버 소유자의 별명은 Discord 제한으로 직접 변경해야 합니다.

## 5. 멘토 업무 안내

Discord 인증 후 아래 안내를 순서대로 확인합니다. 완료 상태는 계정·워크스페이스별로 저장하여 다시 로그인해도 유지합니다. 안내 확인 기록은 실제 과제 생성이나 멘토링 진행 실적을 의미하지 않습니다.

1. **과제 생성:** 온보딩 화면의 과제 만들기에서 과정·제목·마감일을 입력합니다. 과제는 선택한 과정 전체에 공개됩니다. 조 담당 멘토는 담당 조가 속한 과정에 생성할 수 있습니다.
2. **멘토링 예약 승인:** Discord `/멘토 설정`에서 시간대·예약 슬롯을 만들고, 수강생 신청 시 봇이 보내는 DM에서 승인하거나 사유와 함께 거절합니다.
3. **멘토링 진행:** 확정 시간에 담당 조 음성 채널에서 진행하고, 조별 대화 채널에 피드백과 다음 할 일을 공유합니다.

LMS 초대 링크는 관리자가 직접 전달합니다. 기본 정보와 안내 완료 기록, 담당 조는 서버에 저장됩니다. 새 필수 환경변수는 없으며 기존 공통 봇의 `LEARNINGOPS_PROVISION_URL/TOKEN`과 `LEARNINGOPS_AUTH_URL/TOKEN`을 사용합니다. 웹과 봇을 함께 배포해야 변경된 멘토 조별 권한이 적용됩니다.
