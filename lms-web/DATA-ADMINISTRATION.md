# 백업 · 데이터 관리

총관리자 계정으로 로그인한 뒤 **백업 · 데이터 관리** 메뉴를 엽니다. 워크스페이스 관리자·멘토·학생·개발용 공용 관리자 계정은 사용할 수 없습니다. 선택한 워크스페이스에 관계없이 **현재 접속한 웹 서버 전체**가 대상입니다.

## 백업 다운로드

**전체 백업 다운로드**로 `.axbackup` 파일을 저장합니다. 공통 DB의 계정·권한·워크스페이스 설정과 워크스페이스별 학습 데이터, 보관된 워크스페이스, 디스크에 남아 있는 워크스페이스 DB를 포함합니다. WAL에만 있던 최신 기록도 현재 SQLite 연결에서 읽습니다. 백업은 별도 DB로 시험 복구한 후 제공합니다.

파일에는 개인정보와 비밀번호 해시가 포함되며 암호화되어 있지 않습니다. 제한된 저장소에 보관하세요. 서버 환경변수의 비밀키, Discord 서버의 실제 채널·메시지, 외부 첨부파일, 다른 호스트의 봇 원본 DB, 이전 자동 백업 파일은 포함하지 않습니다. 로컬과 운영은 각각 접속하여 다운로드해야 합니다.

## 초기화

1. 백업 파일을 다운로드합니다.
2. **전체 데이터 초기화**를 누르고 현재 총관리자 비밀번호와 `전체 데이터 초기화`를 입력합니다.
3. 서버가 직전 상태의 자동 백업을 만든 뒤 계정·연결·학습 데이터를 비웁니다. 기본 워크스페이스 `default`, `asan-ax`는 다시 생성됩니다.
4. **로그인 화면으로 이동**을 눌러 서버의 최초 관리자 설정 키로 새 총관리자를 등록합니다.

`ADMIN_PASSWORD`가 16자 이상이어야 초기화할 수 있습니다. 이 키는 현재 계정 비밀번호와 다릅니다. 초기화 후 기존 `LEARNINGOPS_AUTH_GUILD_ID`만으로 Discord 연결을 다시 만들지 않습니다. 실제 Discord 리소스와 봇 호스트에 남은 기존 DB는 지우지 않으므로, 기존 봇 DB 재이관을 원하지 않는다면 서버를 다시 연결하기 전에 별도로 정리하세요.

## 복구

1. 이 기능에서 받은 `.axbackup` 파일을 선택하고 **백업 파일 검증**을 누릅니다.
2. 백업 시각·계정 수·워크스페이스 수를 확인합니다. 검증 결과는 같은 총관리자에게 10분간 유효합니다.
3. **이 백업으로 복구**를 누르고 현재 총관리자 비밀번호와 `백업으로 전체 복구`를 입력합니다.
4. 현재 데이터의 자동 백업을 저장한 뒤 전체 데이터를 교체합니다. 백업 당시의 계정·비밀번호로 다시 로그인합니다.

복구는 병합이 아닙니다. 모든 기존 로그인 세션·진행 중인 인증 코드를 폐기합니다. 백업에 있던 대기·진행 중 알림은 발송 보류로 바꾸고, 진행 중 Discord 구축과 초대 발급 작업을 실패 처리하여 이전 발송 권한을 재사용하지 못하게 합니다. 이미 발송된 메시지와 수동 발송 완료 기록은 유지합니다. Discord의 실제 상태는 되돌리지 않습니다.

압축 파일 최대 32MiB, 압축 해제 후 최대 128MiB, DB 최대 200개를 지원합니다. 파일의 형식·버전·SHA-256·테이블·열·값·외래키·DB 무결성을 검사하며 업로드된 SQL은 실행하지 않습니다. 현재 스키마와 호환되는 이 기능의 백업만 지원합니다. 기존 `scripts/lms_backup.py`의 SQLite/manifest 디렉토리는 서버 콘솔 복구 도구로 복구하세요.

## 운영 및 장애 복원

이 기능은 현재 구성처럼 **한 웹 API 프로세스가 DB를 소유하고 봇은 HTTP로 접근하는 환경**을 전제로 합니다. 같은 파일에 접근하는 별도 API 인스턴스나 직접 SQLite writer를 함께 실행하지 마세요.

작업 동안 새 API 요청에는 503을 반환하고, 기존 비동기 계정 처리·봇 DB 작업이 끝날 때까지 최대 30초 기다립니다. 자동 알림 준비·세션 정리도 일시 중단합니다. 시험 복구와 자동 백업이 성공한 뒤 DB 핸들을 닫고 교체하며, 재시작 없이 새 DB 연결을 엽니다. 교체 실패는 원본 전체로 되돌립니다. 교체 중 프로세스가 종료되면 다음 시작 시 저널에 따라 원본으로 자동 복원합니다. 파일시스템 또는 디스크 자체의 고장은 별도 운영 복구가 필요합니다.

- 자동 백업: `<BOT_DB_PATH>.backups/*.axbackup`. 다시 총관리자로 로그인하면 같은 메뉴에서 다운로드할 수 있습니다.
- 교체 저널·원본: `<BOT_DB_PATH>.maintenance/`. 정상 완료 시 정리합니다. 미완료 작업의 디렉토리를 수동 삭제하지 마세요.
- 임시 검증: DB와 같은 부모 디렉토리의 `.ax-restore-<UUID>/`. 정상 종료 시 정리합니다. 프로세스 강제 종료 시 남을 수 있습니다.

DB·워크스페이스·자동 백업·교체 디렉토리를 같은 영속 볼륨에 두고, 복구 준비본과 원본 및 자동 백업을 함께 보관할 공간을 확보하세요. 자동 백업은 자동 삭제하지 않습니다. 운영자가 별도 사본을 확보한 뒤 보관 기간과 디스크 사용량에 따라 정리합니다. 웹 디렉토리나 공개 정적 파일 경로에 두지 마세요.

검증: `npm test`의 데이터 관리 테스트, `npm run build`, `npm run lint`, `npx playwright test tests/data-admin.spec.ts`. 테스트는 임시 DB로 실행합니다.
