# 명단 출결 운영과 장애 복구

이슈 #11 · 마일스톤 #1의 운영자 명단형 출결입니다. Web API가 워크스페이스 SQLite에 직접 저장합니다. 학생은 멘토가 발급한 코드로 Discord에서 출석할 수 있습니다. [코드 출석 운영 안내](./ATTENDANCE-CODES.md)를 확인하세요. 시간 기준 자동 지각 판정은 포함하지 않습니다.

## 수업 운영

1. **출결 관리 → 출결 과정·날짜·차시**를 선택합니다. 차시는 1~100에서 운영자가 지정합니다. 등록된 해당 과정 수강생 전체를 표시하며 재적 상태도 함께 확인할 수 있습니다. 조 멘토에게는 담당 조 명단만 표시됩니다.
2. 관리자 또는 메인 강사가 **회차 시작**을 누릅니다. 상태는 `진행 전 → 진행 중 → 마감`이며 마감된 회차를 다시 열지 않습니다. 기존 단건 기록이 있는 회차를 시작하면 해당 기록을 이어서 관리합니다.
3. **미처리 N명 출석**으로 현재 표시된 정상 수강생의 미처리만 출석으로 바꾼 뒤, 예외 인원은 명단의 `출석 / 지각 / 결석 / 공결` 버튼을 누릅니다. 이름·조·상태 검색과 체크박스로 선택한 인원만 일괄 변경할 수도 있습니다. 필터를 변경하면 선택은 해제되고 저장 전 변경은 유지됩니다. 기본은 미처리이며 자동 결석 처리는 하지 않습니다.
4. **출결 일괄 저장**을 누릅니다. 상단 인원 수는 현재 편집 중인 명단 기준이며, 저장 전 변경 표시가 사라지고 저장 성공 메시지가 나타났는지 확인합니다. 한 요청에 최대 1,000명을 저장합니다. 일부 행이 실패하면 기록·이력·요청 처리가 모두 취소됩니다.
5. 관리자 또는 메인 강사가 과정 전체의 미처리가 0명인지 확인한 뒤 **회차 마감**을 누릅니다. 조 멘토는 담당 범위의 입력·정정만 할 수 있습니다.
6. 마감 후에는 변경할 인원을 선택하고 **등록·정정 사유**를 새로 입력해 저장합니다. 변경 전후 상태·사유·작업자·시간은 **출결 변경 이력**에서 최근 200건까지 확인합니다. 전체 감사 기록은 DB에 보존됩니다.

수강생 화면은 워크스페이스 Discord 인증과 수강 상태 확인을 거쳐 확정된 본인 기록만 표시합니다. 운영자 사유와 다른 수강생 기록은 제외합니다. 기존 단건 방식으로 저장되었고 회차가 없는 과거 기록은 기존 공개 상태를 유지합니다. 관리 회차로 전환한 뒤에는 마감 시점부터 공개합니다. 데모 모드는 기존 단건 입력 화면을 유지합니다.

## 장애 중 기록 → CSV 복구

1. 수업 전에 과정·날짜·차시별 **출결 CSV 내보내기**로 명단을 보관합니다. 미처리 인원도 포함하므로 종이 출력이나 오프라인 기록에 사용할 수 있습니다.
2. Discord 또는 봇만 장애라면 Web에서 그대로 기록합니다. Web/API도 사용할 수 없으면 CSV의 `status`, `reason` 열 또는 종이 명단에 기록합니다. 지각·공결 등을 수기로 판단하고 운영 담당자를 남깁니다.
3. 복구 후 같은 과정·날짜·차시를 선택해 **명단 새로고침**을 누릅니다. 진행 전이면 관리자가 회차를 시작합니다. 종이 기록은 미리 보관한 CSV에 옮깁니다.
4. **출결 CSV 가져오기**를 선택합니다. 가져오기는 편집 화면에만 반영되며 아직 저장하지 않습니다. 상태·인원 수를 확인한 뒤 **출결 일괄 저장**을 누릅니다. 이미 마감했다면 공통 정정 사유를 입력합니다.
5. 저장 성공 메시지와 새로고침 후 결과를 확인합니다. 다른 사람이 먼저 저장해 충돌하면 기존 입력을 CSV로 보관한 뒤 명단을 새로고침하고 최신 기록과 대조해 다시 반영합니다. 자동 덮어쓰기는 하지 않습니다.

CSV는 UTF-8(BOM 포함)이며 열 순서는 `courseId,date,period,studentId,name,team,status,reason`입니다. ID·날짜·차시는 텍스트로 유지하고 열을 삭제하거나 이동하지 않습니다. 다른 과정·회차·권한 밖 인원·중복 인원·알 수 없는 상태가 있으면 파일 전체를 거절합니다. 최대 2MB, 1,000행입니다. 미처리 행은 기존 기록을 삭제하거나 결석 처리하지 않습니다. 파일에 없는 인원도 그대로 유지합니다. 이름·팀은 확인용이고 저장 대상은 수강생 ID로 결정합니다. 내보낸 수식 시작 문자에는 작은따옴표를 붙여 스프레드시트 수식 실행을 방지하며 가져올 때 복원합니다.

## 저장과 충돌 처리

- `GET /api/workspaces/:id/attendance?courseId=...&date=YYYY-MM-DD&period=1`에서 명단·회차 상태·권한·이력·revision을 조회합니다.
- `POST /api/workspaces/:id/attendance`는 같은 선택값과 `requestId`(UUID), `revision`, `action`(`start|save|close`), `entries`를 받습니다. 항목은 `studentId,status,reason`입니다. 상태 전환 요청에 출결 항목을 함께 넣지 않습니다.
- 동일 requestId와 동일 본문 재전송은 중복 저장하지 않습니다. 같은 번호를 다른 내용으로 쓰거나 오래된 revision으로 저장하면 409를 반환합니다. 응답을 잃은 경우 화면에서 같은 저장을 다시 누르면 같은 요청 번호를 재사용합니다.
- 기록·회차·감사 로그·중복 방지 정보를 하나의 `BEGIN IMMEDIATE` 트랜잭션으로 처리합니다. 회차를 관리하기 시작하면 기존 workspace/teaching 단건 변경 경로로 수정하거나 다른 회차로 옮길 수 없습니다.
- 권한은 매 요청 다시 확인합니다. 보관된 워크스페이스는 조회할 수 있지만 출결을 저장할 수 없습니다.

검증: 서버 테스트는 120명 중 마지막 행 저장 오류 시 전체 롤백, 중복 요청, 충돌, 조별 권한, 정정 이력, 확정 기록 공개와 CSV를 확인합니다. `tests/attendance.spec.ts`는 실제 API의 120명 저장·동시 요청·멘토 권한과 브라우저의 CSV 복구·마감·정정·모바일 화면을 확인합니다.

## Discord 출결 집계 공유

명단 아래 **Discord 출결 집계 공유**에서 저장된 집계를 확인하고 발송합니다. 기존 운영자 전용 과제 대시보드 채널을 사용하며, 봇이 비공개 권한을 확인·복구한 뒤 게시합니다. 과정·날짜·차시와 상태별 인원만 보내며 학생 이름·정정 사유는 보내지 않습니다. 조 멘토는 담당 조 집계만, 관리자·메인 강사는 과정 전체를 공유합니다. 검색 필터는 공유 범위를 변경하지 않습니다.

저장 전 변경이 있으면 먼저 저장하세요. 발송 상태는 자동 확인하며 완료 후 메시지 링크를 제공합니다. 동일 저장 버전의 중복 요청은 하나로 처리하고, 확정 실패는 재시도할 수 있습니다. 결과가 불명확하면 기존 메시지만 조회하며 임의로 재발송하지 않습니다. Discord 장애·미연결 상태에서도 출결 저장은 가능합니다.
