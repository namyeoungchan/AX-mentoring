# 공지 발송과 복구

관리자는 **공지 관리**에서 초안을 저장하고 **발송 미리보기 → Discord 발송 요청**을 누릅니다. 과정명과 본문을 공통 공지 채널에 게시하며 멘션은 모두 차단합니다. 채널을 볼 수 있는 모든 구성원이 읽을 수 있으므로 관리자·멘토 전용 초안은 이 경로로 발송할 수 없습니다. 목적지는 워크스페이스의 Discord 서버 구성에서 `notice`로 적용 완료된 채널만 사용하며 브라우저가 임의 지정할 수 없습니다.

요청 후 내용은 고정됩니다. 내용을 바꾸려면 새 공지를 작성합니다. 발송 대기는 Web SQLite에 보관되며 봇이 연결되면 처리합니다. **발송 결과 새로고침**으로 상태, 시도 횟수, 오류, 메시지 링크와 최근 시도 이력을 확인합니다. 봇에는 기존 `LEARNINGOPS_PROVISION_URL`과 `LEARNINGOPS_PROVISION_TOKEN` 설정을 그대로 사용합니다.

- **발송 실패**: 권한 부족·삭제된 채널·요청 제한 등의 원인을 해결한 뒤 **발송 재시도**를 누릅니다. 새 공지를 복제해 재시도하지 않습니다.
- **결과 확인 필요**: timeout이나 봇 중단으로 성공 여부가 불명확한 상태입니다. **기존 메시지 확인**으로 원래 채널의 봇 메시지와 요청 식별자를 조회합니다. 마지막 전송 시도 이후 최대 1,000개 메시지에서 찾지 못하거나 조회 권한이 없으면 자동 재발송하지 않습니다. 운영자가 Discord를 확인합니다.
- **수동 발송**: 먼저 **수동 발송으로 전환**을 눌러 대기 작업을 중지합니다. 발송 중에는 전환할 수 없습니다. 기존 게시 여부를 확인하고 필요한 경우 미리보기를 복사해 게시합니다. 원래 서버·채널의 메시지 링크를 **수동 발송 완료 기록**에 저장합니다. 수동 기록은 운영자의 확인이며 시스템이 메시지 본문까지 검증한 상태는 아닙니다.

초안·발송 대기·이력은 Discord 장애 중에도 유지합니다. Web도 장애이면 미리 확보한 공지 내용을 현장에서 안내하고, 복구 후 자동 발송 여부를 먼저 대사합니다. 운영자 메시지 복사는 멘션 문자를 분리하지만 Discord에서 수정해 붙여넣을 때도 의도치 않은 멘션이 없는지 확인합니다.

한 공지 ID에 하나의 발송 이벤트를 저장하며 claim·lease로 작업을 분리합니다. 완료 응답을 잃으면 lease 만료 후 기존 메시지 조회로 복구합니다. Discord의 nonce 중복 검사 기간은 최근 수분으로 제한되므로 nonce만으로 장기간의 중복 방지를 가정하지 않습니다. [Discord Create Message 문서](https://docs.discord.com/developers/resources/message#create-message)에 따라 멘션 제한과 고정 nonce를 사용하고, 불확실한 전송은 확인 전까지 보류합니다.

Web과 봇을 함께 배포해야 합니다. 로컬 검증에서는 Discord 전송·timeout·권한·채널 삭제·rate limit을 대체 응답으로 시험합니다. 실제 스테이징 채널 발송은 수업 리허설에서 별도 확인합니다.
