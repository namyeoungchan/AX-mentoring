# 팀 배정과 개인별 Discord 반영

관리자는 **팀 관리**, 멘토는 **팀 배정**에서 담당 명단을 확인합니다. 미배정·배정 완료·Discord 미인증·동기화 실패와 적용 대기 상태를 필터링할 수 있습니다.

1. 과정과 이동할 활성 수강생(최대 100명), 목적 팀을 선택합니다. 조 멘토는 현재 담당 수강생을 담당 팀 사이에서만 이동할 수 있습니다. 주 멘토는 기존 전체 담당 범위를 사용합니다.
2. **배정 미리보기**에서 이전/신규 팀, 이동 인원, 현재 팀 인원을 확인합니다. 자동 균형 배정이나 정원 제한은 없으므로 현장 정원과 대조합니다.
3. **팀 배정 저장**은 Web 원장과 변경 전후 감사 기록을 하나의 트랜잭션에 저장합니다. 오류·동시 수정 충돌 시 전체 취소됩니다. 최신 명단을 다시 확인해 저장하세요.
4. Web 팀 변경은 수강생의 본인 화면에도 반영됩니다. Discord 역할 적용은 별도 상태입니다. 봇이 30초마다 동기화하므로 **팀 상태 새로고침**으로 확인합니다. 오래된 보고(2분 이상)는 적용 완료로 표시하지 않습니다.
5. 실패한 구성원만 선택해 **실패 구성원 재시도**를 누릅니다. 다음 poll은 해당 구성원부터 처리하고 이후 정상 주기 동기화로 돌아갑니다.

권한 오류는 봇의 역할·채널 관리 권한을, 역할 순서 오류는 봇 역할이 관리 대상보다 위인지 확인합니다. 서버 미참여는 Discord 서버 참가를, 자기소개 대기는 시작하기 채널의 안내를 확인합니다. 봇/API가 중단되면 Web 배정은 유지되고 결과는 적용 대기로 남습니다. 봇 재시작 후 저장된 역할 목록을 바탕으로 이전 팀 역할을 제거하고 새 팀 역할을 보충합니다. 새 팀 역할 추가가 실패하면 접근이 잠시 제한될 수 있으며, 이전 팀 접근을 먼저 회수해 다른 팀 자료 노출을 막습니다.

잘못 배정했다면 **팀 변경 이력 CSV**에서 이전 팀을 확인하고 동일한 미리보기 절차로 재배정합니다. 최근 워크스페이스 감사 기록 200건 내에서 담당 수강생 변경을 제공합니다. 전체 감사 이력은 DB에 보존합니다. 자동 되돌리기나 운영 DB 직접 편집은 제공하지 않습니다.

구버전 봇은 개인별 보고를 보내지 않으므로 Web과 봇을 함께 배포해야 개인별 적용 완료를 확인할 수 있습니다. Web만 먼저 배포해도 배정 원장은 저장되며 적용 대기로 표시됩니다. 테스트는 Discord 응답을 대체해 부분 실패·권한 오류·재시도와 DB 원자성을 검증하며 실제 Discord 역할 리허설은 별도 수행합니다.
