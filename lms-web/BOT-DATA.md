# 기존 봇 데이터의 웹 이관

기존 Render 봇의 운영 DB를 해당 Discord 서버가 연결된 웹 워크스페이스로 이관합니다. 이후 봇의 조회·제출·예약·평가는 웹 DB에서 처리하며 로컬 DB로 되돌아가서 저장하지 않습니다. Discord 토큰과 연동 키는 계속 환경변수로 보관합니다.

## 이관되는 자료

- 멘토, 예약 가능 시간, 예약 및 승인·반려 상태
- 예약 시간 규칙, 휴무 날짜·요일, 예약 알림 이력
- 과제 내용·주차·제출 방식·입력 항목, 제출 원문·링크
- 과제 알림 및 질문 알림 이력
- 기존 온보딩 참여·완료 기록
- 비밀평가 회차·점수·의견
- 멘토링·과제·참여도·평가 패널 메시지 위치
- 새 온보딩의 역할·채널·진행 상태와 패널 추적 정보

16개 기존 테이블을 건수 제한 없이 읽어 체크섬이 포함된 이관 자료를 만듭니다. 전송 크기는 최대 64MB이며 초과 시 내용을 잘라서 옮기지 않고 전환을 중단합니다. 별도 백업 파일 전송이 필요한 경우 먼저 전송 방식을 확장해야 합니다. 원본 SQLite는 봇의 영속 디스크에 남고, 전송한 자료는 웹에서도 보관합니다.

## 전환 순서

1. 웹 워크스페이스에 기존 봇의 `GUILD_ID` 서버를 연결합니다.
2. 웹 서비스를 먼저 배포합니다. Docker 이미지에는 기존 저장 함수를 실행할 Python 처리기가 포함됩니다.
3. 기존 Render 봇 서비스에 아래 URL과 웹 서비스와 같은 키가 있는지 확인한 후 새 버전을 배포합니다. 별도 봇 복제본을 동시에 실행하지 않습니다.

```dotenv
LEARNINGOPS_PROVISION_URL=https://asanax-learningops-web.onrender.com/api/integrations/discord/provision
LEARNINGOPS_PROVISION_TOKEN=<웹과 같은 키>
```

4. 봇은 운영 모듈을 시작하기 전에 원본을 전송하고 체크섬·등록된 서버·기존 데이터 충돌을 검증합니다. 번호를 유지하며 동일한 자료는 재삽입하지 않습니다. 충돌하면 전체 이관을 취소하고 원본과 오류를 남깁니다.
5. **봇 데이터 · 운영 → 데이터 이관**에서 완료 여부와 각 항목의 건수를 확인합니다. **원본 다운로드**로 전송 자료를 보관할 수 있습니다.

URL 오류나 데이터 충돌이 있으면 새 봇은 이관을 재시도하며 새 Discord 작업을 받기 전에 대기합니다. 실패 상태에서 로컬과 웹에 나누어 저장하지 않습니다. 전환 이후 웹 연결이 끊기면 해당 요청은 실패로 안내되며 로컬에 임시 저장하지 않습니다. 네트워크 응답 유실로 재요청할 때는 같은 요청 번호로 이전 결과를 반환해 중복 생성을 막습니다.

웹에서 기존 번호와 겹치는 운영 자료를 이미 만들었다면 **충돌 확인 필요**로 표시합니다. 두 자료를 자동 삭제하거나 번호를 바꾸지 않습니다. 원본을 다운로드하고 충돌 항목을 확인한 뒤 정리해야 합니다. 이관 완료 후 이전 봇 DB를 다시 덮어쓰는 요청은 거절합니다.

## 웹 관리

**봇 데이터 · 운영**은 전체 관리자와 해당 워크스페이스 관리자에게 제공됩니다.

- **운영 작업**: 멘토 등록·삭제, 예약 시간과 휴무 설정, 예약 승인·반려·취소, 과제 등록·수정·마감·삭제, 비밀평가 시작·마감, 기존 온보딩 완료 처리
- **저장된 자료**: 항목별 조회, 100건씩 페이지 이동. 비밀평가는 평가자 ID를 표시하지 않고 대상별 평균과 의견을 표시합니다. 복구용 원본에는 기존 평가 기록이 그대로 포함되므로 원본은 관리자용입니다.
- **채널 · 역할 설정**: 기존 봇의 채널·역할 ID와 질문 알림 기준을 웹에서 편집. 새 팀과 인원 배정은 기존 **팀 관리·수강생 관리·온보딩 · 팀 연동**을 사용합니다. 자동 온보딩에 연결한 과정이 있으면 해당 팀 목록이 기존 봇의 팀 목록에도 우선 적용됩니다.

과거 자료에 과정 정보가 없으면 기존 봇 자료로 유지합니다. 이름만 보고 임의로 학습 과정이나 회원 계정에 연결하지 않습니다. 과거 운영 자료 조회·수정은 이 화면에서 가능하며, 수강생 학습 화면의 과정별 연결에는 관리자가 과정과 수강생을 등록해야 합니다.

## 자동 게시 오브젝트

선언은 `cogs/panel_objects.py`의 읽기 전용 `PANEL_OBJECTS`입니다. 현재 기존 봇의 운영 패널은 `GUILD_ID` 서버의 DB 인터페이스를 사용하므로 해당 서버에만 게시합니다. 다른 워크스페이스에 아산 자료를 복사해서 게시하지 않습니다. 여러 워크스페이스의 채널 구축과 새 온보딩은 별도 기존 연동으로 계속 동작합니다.

| 채널 | 자동 게시 내용 |
| --- | --- |
| 과제 대시보드 | 과제 현황, 팀 참여도, 활성 비밀평가 진행판 |
| 과제 제출 | 과제 제출 버튼 |
| 멘토링 예약 | 멘토별 예약 버튼 |
| 시작하기 | 새 온보딩 모듈의 자기소개 버튼과 안내 |

봇 시작 시 게시하고 기존 메시지는 수정합니다. 메시지가 삭제되면 다시 만들고 고정합니다. 수동 게시 명령도 같은 오브젝트를 갱신합니다. 사람의 글은 수정하지 않으며 비밀평가 패널 게시가 새 평가 회차를 자동 시작하지는 않습니다. 일반 패널은 5분, 참여도는 1시간 주기로 갱신하고 버튼으로 즉시 갱신할 수 있습니다. 채널·역할 설정은 1분 주기로 확인합니다. Discord 채널 ID는 웹·봇 간 문자열로 전달해 자릿수를 보존합니다.

웹에서 기존 서버의 채널 구성을 다시 적용하면 `assignments`, `mentoring`, `assignment-dashboard` 템플릿 ID와 실제 생성 채널의 연결도 저장합니다. 봇에는 채널 보기·메시지 보내기·기록 보기·링크 삽입·메시지 고정 권한이 필요합니다.

## 실행과 검증

Docker 이외의 웹 실행 환경에는 Python 3.12 이상과 아래 패키지가 필요합니다. 실행 파일 경로는 `PYTHON_EXECUTABLE`로 지정할 수 있습니다. Windows 개발용 `.tools/venv/Scripts/python.exe`가 있으면 자동 사용합니다.

```powershell
python -m pip install -r lms-web/server/requirements-storage.txt
cd lms-web
npm test
npm run test:e2e
```

기존 봇과 웹에서 SQL 문자열을 주고받지 않습니다. 서버는 허용된 기존 저장 함수만 워크스페이스별 DB에서 실행하며, 변경·중복 요청 기록·감사 이력을 한 트랜잭션으로 저장합니다. JSON 전송은 날짜, 집합, 정수 키, Discord ID를 보존합니다. Discord·Render 실서버 이관은 배포 후 위 이관 화면과 봇 로그에서 확인합니다.
